# Синхронизация между устройствами

[← к оглавлению](../README.md) · [English](../en/sync.md)

Синхронизация переносит актуальную версию дневника между всеми твоими устройствами через общее хранилище (облако или WebDAV-сервер). Приложение **не общается с API облака напрямую** — оно лишь читает и пишет файлы; распространением между устройствами занимается выбранный сервис.

---

## Идея: один снимок на устройство

Каждое устройство держит в общем хранилище **ровно один файл** — `device_<id>.json` — со своим **полным состоянием** (все записи, включая «надгробия» удалений, чат, профиль).

Цикл синхронизации:

1. **Читаем** снимки всех *других* устройств.
2. **Сливаем** их в локальную базу.
3. **Перезаписываем** свой снимок (атомарно).

Почему именно так, а не «журнал изменений»: при журнале каждое устройство должно подтвердить получение каждого файла, прежде чем его удалить. Иначе устройство, которое неделю лежало в шкафу, безвозвратно теряет правки. Здесь файл **никогда не удаляется, только перезаписывается** — любое устройство, открыв приложение хоть через год, прочитает текущее состояние. И папка не растёт: один файл на устройство.

## Гарантии безопасности

Синхронизация спроектирована так, чтобы **ни при каких обстоятельствах не уничтожить данные**:

- **Снимок peer'а — не директива, а декларация.** Файл другого устройства говорит «вот что у меня есть», а не «вот что должно быть везде». Слияние только **добавляет** и разрешает конфликты по времени правки. Отсутствие записи у соседа **не означает удаление**.
- **Удаление — только явное «надгробие»** (`deleted=True`), которое корректно реплицируется. Никаких физических удалений, поэтому запись не «воскресает» и всегда восстановима из бэкапа.
- **Атомарная запись** (`во временный файл → переименование`). Сбой посреди записи оставит соседям прежний валидный файл, а не обрезок. Битый/пустой файл при чтении пропускается — локальная база не трогается.
- **Бэкап перед каждым слиянием** (отдельный пул `backups/pre-sync/`). Если что-то пошло не так — «Восстановить» вернёт прежнее состояние.
- **Проверка структуры на импорте.** Запись без обязательных полей пропускается, но остальной снимок применяется — один битый элемент не ломает весь файл.
- **Идемпотентность.** Повторное применение того же снимка ничего не меняет.

**Разрешение конфликтов.** Если одну и ту же дату правили на двух устройствах, побеждает версия с более поздним `updated_at`. Проигравшая версия сохраняется в журнал конфликтов (страница Синхронизация, хранится 30 дней) — её можно посмотреть и при желании перенести вручную.

## Два режима хранилища

### 1. Локальная папка

Папка, которую desktop-клиент облака зеркалит в интернет. Подходит для **любого сервиса с desktop-клиентом**: Dropbox, Google Drive, iCloud Drive, OneDrive, Mega, Sync.com и т.д.

Настройка: на странице **Синхронизация** выбери «Локальная папка» и укажи путь к синхронизируемой папке, например:
```
/Users/you/Dropbox/index-life-sync
C:\Users\you\Google Drive\index-life-sync
```
Указывай **одну и ту же папку** на всех устройствах (внутри своего облака).

### 2. WebDAV-ссылка

Если не хочешь ставить desktop-клиент облака — вставь прямую **WebDAV-ссылку** на папку. Работает с: **Nextcloud, ownCloud, Яндекс.Диск, Box, pCloud, kDrive (Infomaniak)** и любыми self-hosted WebDAV-серверами.

Настройка: выбери «WebDAV-ссылка» и заполни:
- **URL папки** — например `https://dav.example.com/remote.php/dav/files/me/diary/`
- **Логин и пароль** — учётные данные твоего WebDAV-аккаунта (например, аккаунт Nextcloud или «пароль приложения» в Яндексе). Хранятся локально на этом устройстве и отправляются только на указанный сервер.

Кнопка **«Проверить соединение»** заранее покажет, доступен ли сервер и верны ли данные.

> **Чего WebDAV-ссылка не покрывает:** Dropbox, Google Drive, iCloud, OneDrive — у них нет открытого WebDAV (нужен OAuth). Для них используй режим «Локальная папка» через их desktop-клиент.

## Когда происходит синхронизация

- При **старте** приложения (если синхронизация настроена).
- **Периодически** в фоне (каждые ~2 минуты).
- При **сохранении/удалении записи** — твой снимок сразу выгружается (best-effort).
- Вручную — кнопки **«Синхронизировать сейчас»**, **«Экспорт»** (только выгрузить свой снимок), **«Импорт»** (только подтянуть чужие).

---

## Как настроить с нуля (пример)

![Страница «Синхронизация»](../images/sync.png)

1. На устройстве A: страница **Синхронизация** → выбери режим → укажи папку/URL → «Сохранить».
2. Нажми «Синхронизировать сейчас» — в хранилище появится `device_<A>.json`.
3. На устройстве B: укажи **то же** хранилище → «Синхронизировать сейчас». B подтянет записи A и выложит свой `device_<B>.json`.
4. Дальше всё идёт автоматически. Каждое устройство видит снимки всех остальных.

Можно подключать сколько угодно устройств — в папке будет по одному файлу на каждое.

## Бэкапы

Синхронизация и бэкапы — независимые механизмы безопасности:

- **Суточные бэкапы** базы — в `backups/` (последние 10).
- **Бэкап перед слиянием** — в `backups/pre-sync/` (последние 5).
- Восстановление — на странице Синхронизация, затем перезапуск приложения.

Подробнее — [Приложение → Бэкапы](application.md#бэкапы-и-восстановление).

## Подключение телефона (PWA)

Телефонная версия синхронизируется **только в зашифрованном виде** — облако
видит лишь шифротекст. Подключение занимает пару минут:

### Если сначала настроен компьютер (рекомендуемый путь)

1. **Компьютер.** Страница «Синхронизация» → «Найти облачные папки» — выберите
   найденную папку одним кликом (или «Выбрать папку…»). Сохраните.
2. **Компьютер.** Включите сквозное шифрование (пароль-фраза → сохраните ключ
   восстановления).
3. **Компьютер.** В секции шифрования откройте **«Подключить телефон»** —
   появится QR-код.
4. **Телефон.** Настройки → Синхронизация → выберите то же облако
   (Google Drive / Яндекс.Диск) → войдите в аккаунт →
   **«Сканировать код с компьютера»** → наведите камеру на QR.
   Пароль-фраза не понадобится. Если сканер не поддерживается (iOS Safari) —
   введите код с экрана компьютера текстом.
5. Проверка: в «Устройства в этой папке» (на обеих сторонах) появятся два
   устройства с временем последней синхронизации.

### Если сначала настроен телефон

1. **Телефон.** Настройки → Синхронизация → облако → OAuth → придумайте
   пароль-фразу (сохраните ключ восстановления).
2. **Компьютер.** Установите desktop-клиент того же облака (Google Drive /
   Яндекс.Диск), дождитесь синхронизации папок.
3. **Компьютер.** «Найти облачные папки» — папка телефона подсветится как
   «найдена папка синхронизации». Выберите её и сохраните.
4. **Компьютер.** В секции шифрования: введите пароль-фразу — или на телефоне
   откройте «Показать код для подключения компьютера» и введите его на ПК в
   «Ввести код подключения с другого устройства».

### Где лежат папки облаков

- **Google Drive** (macOS): `~/Library/CloudStorage/GoogleDrive-<почта>/My Drive/index.life`
- **Яндекс.Диск**: `<папка Яндекс.Диска>/Приложения/<имя приложения>/`
- Кнопка «Найти облачные папки» ищет эти места автоматически.

> ⚠️ Код подключения (и QR) содержит ключ шифрования дневника. Показывайте его
> только собственным устройствам — не фотографируйте и не пересылайте.

## Каждое облако в деталях

### Google Drive

> ⚠️ **Важно: для связки с телефоном на компьютере нужен режим
> «Google Drive (напрямую)»**, а не «Локальная папка». Телефонное приложение
> работает с узким доступом `drive.file` и видит **только файлы, созданные
> самим index.life**. Файлы, загруженные программой Google Drive на
> компьютере, для телефона невидимы — через зеркальную локальную папку
> синхронизация получается односторонней: компьютер видит телефон, а
> телефон записи с компьютера **не получает**.

- **Телефон:** Настройки → Синхронизация → Google Drive → вход в аккаунт.
  Приложение создаёт папку `index.life` в корне «Мой диск».
- **Компьютер:** страница Синхронизация → режим **«Google Drive
  (напрямую)»** → **«Войти в Google»** (тот же аккаунт, что на телефоне) →
  согласие в браузере. Всё: программа Google Drive на компьютере не нужна,
  пути к папкам искать не надо, обе стороны видят друг друга.
- **Локальная папка Google Drive** остаётся рабочим вариантом для связки
  **компьютер ↔ компьютер** (без телефона).

<details><summary>Для сборщика: как включить прямое подключение в сборке</summary>

Нужен OAuth-клиент типа **Desktop app** из **того же проекта Google
Cloud**, что и веб-клиент телефонного приложения (видимость `drive.file`
считается по проекту — поэтому обе стороны видят файлы друг друга):
console.cloud.google.com → APIs & Services → Credentials → Create
Credentials → OAuth client ID → Desktop app. Затем при сборке/запуске:

```bash
export GOOGLE_DESKTOP_CLIENT_ID="…apps.googleusercontent.com"
export GOOGLE_DESKTOP_CLIENT_SECRET="…"
```

Для установленных (desktop) приложений Google считает client secret
неконфиденциальным — включать его в сборку допустимо по правилам Google.
</details>

### Яндекс.Диск

- **Телефон:** Настройки → Синхронизация → Яндекс.Диск → вход. Работает в
  России без VPN. Данные лежат в папке приложения:
  `Диск → Приложения → <имя приложения>`.
- **Компьютер, способ 1 (проще):** установите десктопный Яндекс.Диск —
  папка приложения зеркалится в `<Яндекс.Диск>/Приложения/…`;
  «Найти облачные папки» подсветит её.
- **Компьютер, способ 2 (без клиента):** режим «WebDAV-ссылка» с адресом
  `https://webdav.yandex.ru/Приложения/<имя приложения>/`. Логин — ваш
  логин Яндекса, пароль — **пароль приложения** (создаётся в
  [id.yandex.ru → Безопасность → Пароли приложений](https://id.yandex.ru/security/app-passwords)),
  обычный пароль аккаунта не подойдёт.

### Dropbox / iCloud Drive / OneDrive / Mega и другие

У этих сервисов нет телефонного клиента index.life — они подходят для
синхронизации **между компьютерами**: поставьте их десктопный клиент на оба
ПК и укажите одну и ту же папку (например `Dropbox/index.life`) через
«Найти облачные папки» или «Выбрать папку…».

### Nextcloud / ownCloud / свой сервер (WebDAV)

Режим «WebDAV-ссылка»: адрес папки вида
`https://ваш-сервер/remote.php/dav/files/логин/index-life/`, логин и пароль
от сервера. Используйте только **https** — по http пароль и дневник идут
открытым текстом (приложение предупредит). Кнопка «Проверить соединение»
покажет, что настройки верны.

## Сценарии

### Два компьютера

1. ПК №1: папка облака → сохранить → включить шифрование → сохранить ключ
   восстановления.
2. ПК №2 (тот же облачный аккаунт, клиент установлен): «Найти облачные
   папки» → выбрать ту же папку → в секции шифрования ввести пароль-фразу
   (или код подключения с ПК №1).

### Новое устройство взамен старого / восстановление

Дневник целиком восстанавливается из облака: настройте папку/облако как
обычно и введите пароль-фразу (или ключ восстановления, если пароль-фраза
забыта). Все записи приедут при первой синхронизации.

### Только телефон, без компьютера

Облачная синхронизация всё равно полезна — это зашифрованный бэкап:
телефон утонул → новый телефон → то же облако → пароль-фраза → всё на месте.

### Совсем без облака

Записи защищены тремя слоями даже без синхронизации:

1. **Постоянное хранилище** — приложение просит браузер не вытеснять данные
   (запрашивается автоматически после первого сохранения; статус — в
   «Сохранность данных»).
2. **Внутреннее зеркало** — вторая копия всех записей в отдельном хранилище
   браузера; если основная база повреждена или вытеснена, записи
   восстанавливаются автоматически при следующем открытии.
3. **Резервный файл (JSON)** — «Сохранность данных» → «Сохранить файл»:
   точная копия всех записей одним файлом. Импортируется обратно без потерь
   (сливается по тем же правилам, что и облачная синхронизация — ничего не
   перезапишет и не удалит). Делайте его иногда и храните вне телефона.

### Перенос из браузера в установленное приложение

- **Android / Chrome:** ничего делать не нужно — вкладка браузера и
  установленное приложение видят одни и те же данные.
- **iPhone / Safari:** приложение с домашнего экрана получает **отдельное**
  хранилище. Перенос: в Safari-версии «Сохранность данных» → «Сохранить
  файл» → в установленном приложении «Импортировать файл». Или подключите
  облако в обеих версиях — они сольются сами.

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| На ПК баннер «Другое устройство синхронизируется с шифрованием…» | ПК не знает ключ. Введите пароль-фразу в секции шифрования — или код подключения с телефона. |
| Телефон: «Код не подходит к данным этого облака» | Телефон подключён не к тому облаку или аккаунту, что компьютер. Проверьте аккаунт и повторите скан. |
| Телефон: «⚠ Не удалось расшифровать данные N устройств» | У какого-то устройства другой ключ (например, оно создало свой vault в другой папке). Переподключите его кодом с работающего устройства. |
| Устройство не появляется в «Устройства в этой папке» | Устройства смотрят в разные папки. На ПК проверьте путь («Найти облачные папки» покажет, где лежат данные телефона); подождите синхронизацию облачного клиента. |
| Телефон: «Сессия облака истекла» | Токен облака протух. Нажмите «Войти заново» — данные не пострадали. |
| «Последняя синхронизация» обновляется, а записей нет | Смотрите баннер над ней: там написано, какой файл не читается и почему. Подробности — в index-life.log на ПК. |
| Забыта пароль-фраза | Введите ключ восстановления (показывался при включении шифрования). Если утерян и он — данные в облаке нечитаемы; локальные записи на устройствах целы, выключите шифрование и настройте заново. |
